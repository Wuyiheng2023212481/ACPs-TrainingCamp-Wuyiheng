这个项目是我去年完成的由潘大发老师指导的实习任务，经过学长的讲述与协助，我自主搭建的一套完整的卫星移动通信仿真系统。当我们亲手把书本上孤立的采样定理、Turbo编码和TCP握手拼接成一条端到端的数字链路时，才真正意识到通信系统的精妙不在于单一模块的极致性能，而在于跨层级数据格式对齐与参数博弈中的那种脆弱平衡，这种在代码报错与波形畸变中摸索出的系统观，远比单纯推导公式更能触及通信的本质。

## 📡 项目概览

这是一个基于 Flask 框架构建的**简化卫星移动通信仿真系统**。它从底层物理信号出发，一直模拟到上层网络协议的传输，完整复现了卫星移动终端从信号采集、编码、协议握手、调制解调到星上交换的整个通信流程。通过这个项目，我们不仅验证了《现代通信技术》与《数字信号处理》中的经典理论，更重要的是，我们将那些停留在纸面上的公式——比如奈奎斯特采样定理、香农极限、Turbo 编码增益——变成了屏幕上跳动的数据点和可视化的波形图。

---

## 🚀 核心功能模块

我们的系统采用了高度模块化的设计，通过 Web 界面将六个子课题的功能无缝串联起来，你可以把它想象成一个“乐高积木”式的通信系统：

**1. 信号采集与重建（AD/DA 转换子系统）**
这是整个链路的起点。我们实现了对正弦波、方波、锯齿波、三角波及白噪声等多种模拟信号的数字化过程。你可以在前端自由调节信号的频率（1-10Hz）、幅度（0.1-1）以及关键的采样率（2-20kHz）和量化位数（8/12/16bit）。系统会实时绘制出原始模拟信号、离散采样点以及经过零阶保持重建后的信号，并直接计算 SNR（信噪比）和奈奎斯特频率。实测数据显示，当采样率为 8kHz 时，完美满足了 Nyquist 定理，而将量化位数提升至 16bit 时，SNR 会有显著提升。

**2. 纠错编码与解码（Turbo 编码子系统）**
为了对抗卫星信道中恶劣的信噪比环境，我们实现了经典的 1/3 码率 Turbo 编码器。该模块包含一个简单的逆序交织器和两个卷积编码器，并支持多达 5 次迭代的软判决解码。在实验中我们发现，在信噪比为 5dB 的极端条件下，Turbo 编码能将误码率（BER）从原始的 0.12 降低到 0.003，这种“编码增益”在可视化界面上体现得非常直观。

**3. 可靠传输协议（TCP 三次握手模拟）**
考虑到卫星链路固有的长时延（270ms 左右），我们专门模拟了 TCP 的三次握手过程。这个模块允许你手动设置丢包率（0-1），以此来观察不同网络状况下的连接成功率。数据显示，当丢包率达到 0.3 时，握手成功率会呈指数级下降至 30%，这也解释了为什么卫星通信通常需要特殊的传输层优化机制。

**4. 频带传输（调制解调子系统）**
这里实现了 BPSK 和 QPSK 两种调制方式。系统会生成 I/Q 两路基带信号，并通过载波调制到中频。最酷的一点是，你可以在星座图上实时看到添加了高斯白噪声后的信号点散布情况。QPSK 在频谱效率（2bps/Hz）和抗噪能力（Eb/N0 要求 9dB）之间取得了很好的平衡，这也是我们将其设为默认方案的原因。

**5. 星上交换与路由（交换子系统）**
模拟了卫星作为中继节点的路由选择功能。系统预设了三条路径：地面站 A、地面站 B 和中继站。它会根据预设的延迟和带宽参数自动选择最优路径（默认首选低延迟高带宽的地面站 A），并记录所有的路由历史，让你清晰地看到流量的分发情况。

**6. 波束控制（波束复用控制）**
虽然这是一个相对简化的模块，但它依然展示了卫星如何通过调整波束角度（0-360°）来对准不同的覆盖区域，并支持 FDMA/TDMA 模式的切换，体现了多波束卫星的资源分配思想。

## 🛠️ 技术栈与运行环境

*   **后端框架**: Python + Flask

## 💡 实验心得与设计反思

在完成这个项目的八周时间里，我经历了从“纸上谈兵”到“真枪实战”的转变。

**关于级联匹配的教训**：  
在全链路集成的过程中，我们遇到了一个典型的工程问题：AD/DA 模块输出的是 `float32` 数组，而 Turbo 编码器却要求 `uint8` 二进制输入。这种“数据格式冲突”在理论课上从未被提及，却是实际工程中导致系统崩溃的常见原因。最终我们通过编写数据格式转换接口解决了这个问题，这让我们深刻理解了“接口定义”在系统工程中的重要性。
