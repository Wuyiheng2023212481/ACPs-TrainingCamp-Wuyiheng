这是我在大二上学期选修JAVA编程语言时独立设计并实现的一个基于字符界面的C/S结构的简易聊天室程序，把那些书本上枯燥的Java网络编程和多线程概念真正落地。它帮我更好地认识了“Socket通信”和“并发”这两个问题，建立了“系统设计”的初步概念。

---

## 一、 项目总体结构设计

我严格遵循**C/S（客户端/服务器）架构**，采用**分层分包**的设计思想，将网络通信、业务逻辑与用户界面解耦。整体结构清晰，主要包含以下三个层次：

### 1. 服务器端 (Server Layer)
位于 `src/server/` 目录下，是程序的核心控制中枢。
*   **网络接入层**：由 `ChatServer` 负责，承担端口监听（8888端口）、接收客户端连接、管理线程池的任务。
*   **业务处理层**：由 `ClientHandler` 实现，采用“一客户一线程”模型，专门处理单个客户端的认证、消息解析与转发。
*   **数据管理层**：由 `UserManager` 和 `User` 组成。`UserManager` 负责从文件加载用户数据及在线状态维护；`User` 是实体类，封装了用户名、密码等属性。

### 2. 客户端 (Client Layer)
位于 `src/client/` 目录下，负责用户交互。
*   **界面交互层**：由 `ClientUI` 实现，基于命令行界面（CLI），负责接收用户输入并显示服务器返回的信息。
*   **通信层**：在 `ClientUI` 内部实现，负责建立Socket连接并收发数据流。

### 3. 数据存储
*   **用户文件 (`users.txt`)**：以明文形式存储用户名和密码，用于登录验证。
*   **日志文件 (`server.log`)**：用于持久化记录用户的关键行为轨迹。

## 二、 核心应用过程分析

整个系统的运行流程可以分为**启动初始化**、**连接与认证**、**消息处理**及**异常处理**四个阶段。

### 1. 服务器启动与初始化过程
1.  **加载配置**：`ChatServer` 启动时，首先实例化 `UserManager`。
2.  **读取用户库**：`UserManager` 从 `users.txt` 文件中读取所有合法用户数据，将其加载至内存的 `HashMap` 结构中，便于O(1)时间复杂度查找。
3.  **端口侦听**：服务器在固定端口（8888）创建 `ServerSocket`，进入阻塞状态，等待客户端连接。
4.  **启动管理线程**：同时启动一个独立的控制台线程，允许管理员输入 `list`、`listall`、`quit` 等指令管理系统。

### 2. 客户端连接与会话建立
1.  **发起连接**：客户端 `ClientUI` 启动，创建 `Socket` 对象指向服务器IP和端口。
2.  **双工通道建立**：连接成功后，客户端立即开启一个**后台读取线程** (`readServerMessages`)，专门用于异步接收服务器推送的消息，防止主线程阻塞。
3.  **三次握手模拟**：
    *   服务器接受连接，检查在线人数是否超过上限（5人）。
    *   若未超限，创建 `ClientHandler` 对象放入线程池执行。
    *   客户端在控制台提示输入用户名和密码，并通过输出流发送至服务器。

### 3. 身份认证机制 (Authentication Flow)
1.  **凭证校验**：`ClientHandler` 接收到用户名和密码后，调用 `UserManager.authenticate()` 方法进行比对。
2.  **失败重试逻辑**：
    *   若验证失败，服务器记录“登录失败”日志（含IP和时间），并向客户端发送错误提示。
    *   客户端会循环提示重新输入，直至成功或输入 `quit` 退出。
3.  **成功回调**：
    *   验证通过后，标记用户为在线状态，绑定IP地址。
    *   服务器记录“登录成功”日志，并向全体在线用户广播“XXX加入了聊天室”的通知。

### 4. 聊天消息处理流程 (Message Handling)
客户端输入被分类处理，体现了系统的核心交互逻辑：

| 输入类型 | 格式示例 | 处理逻辑 | 触发代码位置 |
| :--- | :--- | :--- | :--- |
| **广播消息** | `你好大家` | 服务器遍历所有在线客户端 `ClientHandler`，调用 `sendMessage` 发送。 | `handlePublicMessage` |
| **私聊消息** | `@Alice 你好` | 解析 `@` 后的用户名，在在线列表中精准定位目标 `ClientHandler` 发送。 | `handlePrivateMessage` |
| **系统命令** | `@@list` | 不以 `@@` 为前缀的命令（如 `list`, `quit`, `anonymous`）被拦截，不进入聊天流，直接执行服务端逻辑。 | `handleCommand` |

**匿名模式切换**：当客户端输入 `@@anonymous` 时，会翻转 `anonymousMode` 标志位。在发送消息时，若标志位为真，则发送者显示为“匿名用户”，而非真实ID。

### 5. 日志与退出机制
*   **日志记录**：系统在关键节点（登录成功、登录失败、退出）调用 `logEvent` 方法，采用追加写模式将格式化日志（时间戳 - 用户名 - 事件 - IP）写入 `server.log`。
*   **优雅退出**：当客户端输入 `@@quit` 或连接异常中断时，`disconnectClient` 方法会被调用，释放Socket资源，更新用户在线状态，并通知其他用户该用户已下线。

## 三、 总结

我的项目通过**多线程并发模型**解决了单服务器服务多客户端的问题，利用**命令模式**（以 `@@` 区分）实现了业务逻辑的灵活扩展。其结构符合基础网络编程的教学要求，数据流清晰，异常处理闭环，完整地实现了从用户认证、在线聊天到行为审计的全过程。
